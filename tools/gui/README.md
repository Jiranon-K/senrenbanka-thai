# ตัวติดตั้งแบบหน้าต่าง

โปรแกรม Windows จริงๆ — widget ของระบบล้วน มีปุ่มบน taskbar มี Alt-Tab
**ไม่มีเบราว์เซอร์ ไม่มี HTTP server ไม่เปิดพอร์ต ไม่ต้องพึ่ง WebView2**

หน้าต่างไม่มีแถบหัวของ Windows — วาดเองตามดีไซน์ (เครื่องหมาย + ชื่อ + เวอร์ชัน + ปุ่มย่อ/ปิด)
พร้อมกรอบ 1px รอบหน้าต่าง

ทำงานเหมือน `install.bat` ทุกประการ แต่หาโฟลเดอร์เกมให้เอง จึงแตกซิปไว้ที่ไหนก็ได้

ดีไซน์มาจาก Claude Design — โปรเจกต์ *Fan-translation mod installer*,
ไฟล์ `Mod Installer.dc.html` (ระบบดีไซน์ **Modernist**)

## Stack

| ชั้น | เลือกอะไร | ทำไม |
|---|---|---|
| หน้าต่าง | **tkinter** (มากับ Python) | เป็น Win32 window จริง ไม่มี dependency เพิ่ม และ `.exe` เล็กสุด |
| หน้าตา | Frame/Label/Canvas + สีจากโทเคนดีไซน์ | Modernist ใช้ `--radius: 0px` ไม่มี gradient ไม่มีเงาในตัว panel — ยกมาเป็น native widget ได้ครบโดยไม่เสียรายละเอียด |
| ตรรกะ | Python (`core.py`) | toolchain เดียวกับ pipeline แปล และเทสได้โดยไม่ต้องเปิดหน้าต่าง |
| อนิเมชัน | `anim.py` เขียนเอง (~230 บรรทัด) | Tk ไม่มีระบบ animation และห้ามเพิ่ม dependency — เอาแนวคิดของ anime.js มา: duration + easing + ตัวจับเวลากลางตัวเดียว |
| แพ็ก | PyInstaller `--onefile --windowed` | ผู้เล่นได้ไฟล์เดียว ไม่ต้องลง Python |
| ฟอนต์ | Sarabun (OFL) bundle มาด้วย | โหลดเข้า process ด้วย `AddFontResourceExW` ไม่ต้องติดตั้งลงเครื่องผู้เล่น |

### ทำไมไม่ใช้ WebView2/pywebview

รอบแรกทำด้วย pywebview + WebView2 แล้ววัดได้ว่ามัน **ตั้ง HTTP server ที่
`127.0.0.1` แล้วโหลดหน้าเว็บผ่านพอร์ตนั้น** — เป็น web app ในกรอบหน้าต่างจริงๆ
ไม่ใช่โปรแกรมหน้าต่าง แถมยังเปิดพอร์ตทิ้งไว้ (มีสิทธิ์โดน firewall ถาม)
และพังทั้งใบถ้าเครื่องไม่มี WebView2 Runtime

Tk เรนเดอร์ไทยถูกด้วย: `test_app.py` วัดว่า `width("ที่") == width("ท")`
คือสระ/วรรณยุกต์ **ซ้อน** ไม่ใช่เรียงต่อกัน (เทสไว้ 3 คู่ กันไว้เผื่อ Tk
เปลี่ยน text engine ในอนาคต)

## รัน / build

```powershell
# ต้องมีชุดติดตั้งที่ build_release.py สร้างไว้ก่อน (manifest.json + *.xdelta + xdelta3.exe)
$env:SBTP_RES = "thai_work\dist\senrenbanka-thai-patch-v1.1"

python tools/gui/app.py                 # รันจาก source
python tools/gui/test_core.py           # เทสตรรกะ
python tools/gui/test_app.py            # เทสหน้าจอ (มีเคสที่ขยับเมาส์จริงราว 1 วิ)
python tools/gui/test_app.py --no-input # ข้ามเคสที่ต้องฉีด input
python tools/gui/build_gui.py --out thai_work\dist\senrenbanka-thai-patch-v1.1
```

เคส "ลากด้วยเมาส์จริง" ฉีด input เข้าระบบจริงๆ เพื่อเทสทั้งเส้น (Windows →
Tk → handler → หน้าต่างขยับ) มันจะเช็กก่อนเสมอว่าจุดที่จะกดเป็นหน้าต่างของ
เราเอง ถ้ามีหน้าต่างอื่นบังอยู่จะข้ามเคสนั้นไป ไม่กดมั่ว และคืนตำแหน่ง
เคอร์เซอร์ให้ตอนจบ

สร้าง `ui/bg.png` ใหม่ (ทำเมื่อเปลี่ยนภาพเท่านั้น ไม่ได้อยู่ในขั้นตอน build ปกติ):

```powershell
python tools/gui/make_bg.py "...\ภาพ.jpg" --focus 0.20,0.02 --zoom 1.35 `
       --peak 0.88 --clear 0.30 --wash 0.09 --desat 0.16 --blur 2.7
```

สร้างโลโก้ + ไอคอนใหม่:

```powershell
python tools/gui/make_logo.py "...\ภาพ.jpg" --focus 0.513,0.01 --zoom 1.45
```

หรือทำทั้งชุดรวด: `python tools/build_release.py --version 1.1 --gui`

`SBTP_RES` มีไว้ตอนพัฒนาเท่านั้น — ตัว `.exe` จริงอ่านไฟล์ที่วางอยู่ข้างๆ ตัวเอง

## ลากหน้าต่าง: ทำไมไม่ใช้ `wm geometry`

อาการที่เจอคือลากแถบหัวแล้วเห็นหน้าต่างเป็นเงาตามหลังเคอร์เซอร์ แล้วกระโดดตามทีเดียว
วัดออกมาได้ชัดเจน:

| วิธี | เวลาต่อเฟรม | เพดาน |
|---|---|---|
| `root.geometry("+x+y")` (ของเดิม) | **30.6 ms** | 33 fps |
| `SetWindowPos` ตรงๆ | **0.49 ms** | ~2000 fps |

`wm geometry` ไม่ได้แค่ย้ายหน้าต่าง — Tk รื้อผังหน้าต่างใหม่ทุกครั้งที่สั่ง
เมาส์ส่ง event มา 125-1000 Hz แต่ handler รับได้ 33 ครั้ง/วินาที คิวจึงบวม
หน้าต่างตามหลัง (= เงา) แล้วกระโดดไปตำแหน่งล่าสุดตอนคิวระบาย (= วาป)

**ทำไมไม่ยกให้ Windows ลากเอง** (`WM_NCLBUTTONDOWN`/`HTCAPTION` ซึ่งเป็นวิธี
มาตรฐานของโปรแกรมที่วาดแถบหัวเอง และได้ Aero Snap มาฟรี) — ลองแล้วใช้กับ Tk ไม่ได้
เพราะลูปย้ายหน้าต่างของ Windows เป็น modal loop:

* `SendMessage` ไม่คืนค่าจนกว่าจะลากเสร็จ เราจึงค้างในสาย ctypes ที่ปล่อย GIL ทิ้งไว้
  ระหว่างนั้นลูปยิงข้อความกลับเข้า window proc ของ Tk ซึ่งเรียก `Tcl_ServiceAll()` ต่อ
  แล้ววิ่งเข้าโค้ด Python ทั้งที่ไม่มี GIL → **ล่ามตายคาที่**
  (`Fatal Python error: PyEval_RestoreThread`) เทสจับได้ตอนลากด้วยเมาส์จริง
* `PostMessage` คืนทันที GIL ปลอดภัย แต่ลูปเริ่มในรอบ event ถัดไป ถ้าผู้ใช้คลิกเร็ว
  จนปล่อยปุ่มไปก่อน ลูปจะเริ่มตอนไม่มีปุ่มถูกกด แล้วสลับเป็นโหมดย้ายด้วยปุ่มลูกศร
  = หน้าต่างติดหนึบตามเมาส์จนกว่าจะคลิกหรือกด Esc ซึ่งแย่กว่าอาการเดิม

ที่ยอมเสียไปคือ Aero Snap อย่างเดียว

## อนิเมชัน

ยึดสามข้อ:

1. **ตัวจับเวลาตัวเดียว** สำหรับทวีนทุกตัว เดินเฉพาะตอนมีงาน หมดงานแล้วหยุด
   (ถ้าปล่อยให้แต่ละอนิเมชันเรียก `after()` เอง งานจะซ้อนกันจน Tk ตามไม่ทัน
   ซึ่งเป็นอาการเดียวกับที่เพิ่งแก้ไป)
2. **อ้างนาฬิกาจริง ไม่นับเฟรม** เฟรมตกก็ยังจบตรงเวลา
3. **เคารพค่าของผู้ใช้** ถ้าปิด "Animation effects" ใน Windows ไว้ ข้ามทั้งหมด
   (`SPI_GETCLIENTAREAANIMATION`) หรือสั่ง `SBTP_NO_ANIM=1`

| ที่ไหน | ทำอะไร | จังหวะ |
|---|---|---|
| เปิดโปรแกรม | ไล่ความทึบ 0→1 | 200 ms `out_quad` |
| เปลี่ยนหน้า | เนื้อหาเลื่อนขึ้น 14 px + ไล่สีตัวหนังสือขึ้นจากพื้น | 300 ms `out_cubic` |
| แถบขั้นตอนซ้าย | ขีดของขั้นที่ทำอยู่ยืด 14→22 px + ไล่เป็นสี accent | 340 ms `out_cubic` |
| รายการที่จะติดตั้ง | กล่องติ๊กเด้งขึ้นทีละแถว (stagger) | 260 ms ห่างกัน 55 ms |
| กล่องติ๊ก | จุดกลางโตเลยขนาดจริงแล้วยุบกลับ | 260 ms `out_back` |
| แถบความคืบหน้า | ไล่เข้าหาเป้า ตัวเลข % เดินตามแถบ | 280 ms `out_cubic` |
| ปุ่ม | เมาส์เข้า/ออกไล่สี — **แต่ตอนกดเปลี่ยนทันที** | 130 ms `out_quad` |
| ตราสำเร็จ/ล้มเหลว | ลากเส้นทีละนิดเหมือนเขียนด้วยมือ | 380 ms |
| หน้าล้มเหลว | หน้าต่างสั่นซ้าย-ขวาเบาๆ | 420 ms |
| ปิดโปรแกรม | จางออกแล้วค่อยปิด | 120 ms |

ที่จงใจ**ไม่**ทำ: แถบความคืบหน้าไม่มีลูกเล่นวิ่งหลอกตา ปลายทางยังเป็นตัวเลข
เดียวกับที่ `core.py` รายงานเสมอ — เป็นอนิเมชันเพื่อให้ตาอ่านทิศทางออก
ไม่ใช่เพื่อกลบว่างานช้า


## โลโก้กับไอคอน

เครื่องหมายมุมบนซ้ายและไอคอนหน้าต่าง/taskbar มาจากภาพเดียวกัน ครอปเป็น
จัตุรัสรอบใบหน้าแล้วย่อด้วย bicubic ของ GDI+ ตอน build (`make_logo.py`)

**ทำไมต้องเตรียมโลโก้ไว้หลายขนาด** — Tk ย่อภาพได้แค่หารด้วยจำนวนเต็มแบบ
nearest-neighbour (`subsample`) ซึ่งขอบแตกทันทีที่ย่อ และย่อเป็นทศนิยมไม่ได้เลย
จอ 125% ต้องการโลโก้ 25 px ซึ่งย่อจาก 40 ไม่ลงตัว จึงสร้างไฟล์แยกไว้ทุกระดับ
(20/25/30/40 = 100/125/150/200%) แล้วให้แอปหยิบไฟล์ที่ใกล้ที่สุดไปใช้ตรงๆ

**ไอคอนเก็บเป็น PNG ข้างใน .ico** — รูปแบบที่ Windows อ่านได้ตั้งแต่ Vista
จึงไม่ต้องเขียน BMP + AND mask เอง และได้ขอบโปร่งใสมาฟรี มีครบ
16/20/24/32/48/64/128/256 px เพราะ Windows หยิบไปใช้คนละขนาดกัน
(taskbar 32, รายการไฟล์ 16, Alt-Tab 48, ไทล์ใหญ่ 256)

ถ้าไม่มีไฟล์เหล่านี้ แอปถอยไปใช้สี่เหลี่ยมส้มตามไฟล์ดีไซน์เดิม
(`theme.make_icon`) — รันจาก source โดยยังไม่ได้สร้างภาพก็ยังทำงานครบ


## แผงภาพพื้นหลัง

ภาพประกอบแบบกระจกฝ้าอยู่ทางขวา ไล่จางหายไปทางคอลัมน์เนื้อหา และเลื่อนเข้าที่
ตอนเปิดโปรแกรม (ขอบที่ไล่จางกวาดผ่าน เลยดูเหมือนแผ่นกระจกเลื่อนเข้ามา)

**ข้อจำกัดที่กำหนดทุกอย่าง: Tk ไม่มีความโปร่งใสระหว่าง widget**
`tk.Label` พื้นขาวคือสี่เหลี่ยมขาวทึบเสมอ วางทับภาพเมื่อไหร่คือบังทันที
จะเอาภาพไปไว้ "ข้างหลังทั้งหน้าต่าง" แบบเว็บไม่ได้เลย

ทางออกคือวางแผงลงบน**พื้นที่ที่ไม่มี widget อยู่จริงๆ** ซึ่งคำนวณจากผังได้ตรงๆ:

```
x = 212 (แถบซ้าย) + 30 (ระยะขอบ) + 420 (คอลัมน์เนื้อหา) = 662 → 880
y = 44 (ใต้แถบหัว) → 526 (เหนือแถวปุ่ม)
```

ได้แผง 218x482 ที่ไม่ทับอะไรเลย ส่วนขอบทั้งสามด้าน (ซ้าย/บน/ล่าง) ถูกไล่จาง
เป็นศูนย์ในช่อง alpha อยู่แล้ว จึงไม่มีรอยตัดให้เห็น แม้บนจอ DPI สูงที่ canvas
ใหญ่กว่าตัวภาพ (วางชิดขวากึ่งกลางแนวตั้ง ช่องว่างจะไปโผล่ด้านที่จางอยู่แล้ว)

`ui/bg.png` กว้าง 280 แต่ 30% ทางซ้ายใสสนิท — เผื่อไว้ให้ canvas ตัดทิ้ง
ขอบซ้ายที่ผู้ใช้เห็นจึงเป็นศูนย์พอดีเสมอ

### ทำไมต้องแปลงภาพตอน build (`make_bg.py`)

* Tk อ่านได้แค่ PNG / GIF / PPM — **ไม่มี JPEG**
* ห้ามลาก Pillow เข้ามาเพื่องานนี้งานเดียว (`.exe` โตขึ้นหลาย MB)
* เบลอ / ลดความอิ่มสี / ไล่จาง ทำตอนรันคือเสียเวลาเปิดโปรแกรมฟรีๆ
  ทั้งที่ผลลัพธ์เหมือนเดิมทุกครั้ง

ถอดรหัส JPEG ด้วย **GDI+ ผ่าน ctypes** — มีในทุกเครื่อง Windows ไม่ต้องลงอะไร
และให้ GDI+ ย่อ/ขยายแบบ bicubic ให้ด้วย ส่วน "ฝ้า" ใช้วิธีย่อแล้วขยายกลับ
(ได้เบลอนุ่มๆ แทบไม่มีต้นทุน แทนที่จะวน box blur ใน Python)

Tk 8.6 ผสม alpha ให้ตรงเป๊ะ (วัดแล้ว: ทับขาว 25/50/75% ได้ค่าตรงทุกจุด)
จึงฝังการไล่จางไว้ในช่อง alpha ได้เลย ตัวแอปเหลือแค่ "วาง" กับ "เลื่อน"
ซึ่งเลื่อนภาพบน canvas วัดได้ **0.01 ms/เฟรม**

### ลิขสิทธิ์

ภาพจากเกมเป็นของผู้พัฒนา `make_bg.py` กับ `make_logo.py` จึงรับ path จาก
ภายนอกและไม่เก็บไฟล์ต้นฉบับไว้ในที่เก็บโค้ด — ส่วนไฟล์ใน `ui/` ที่ถูก commit ไว้
เป็นภาพที่ผ่านการครอป/ย่อ/เบลอ/ไล่จางแล้ว

ถ้าจะแจกจ่ายเป็นสาธารณะ ควรพิจารณาเปลี่ยนไปใช้ภาพของตัวเอง — ชี้ทั้งสอง
สคริปต์ไปที่ไฟล์อื่นได้เลย และถ้าลบไฟล์ใน `ui/` ทิ้ง ตัวติดตั้งก็ยังทำงาน
ครบทุกอย่าง (ไม่มีแผงภาพ ไอคอนกลับไปเป็นสี่เหลี่ยมส้มตามดีไซน์)


## ตัดสินใจอะไรไว้บ้าง

**ถอดแถบหัวของ Windows ด้วยการล้างบิต ไม่ใช่ `overrideredirect`** —
`overrideredirect(True)` ทำให้หน้าต่างหลุดจากการจัดการของ window manager:
ปุ่มบน taskbar หาย Alt-Tab หาย `iconify()` เพี้ยน
การล้างเฉพาะ `WS_CAPTION | WS_THICKFRAME` เอาแค่หน้าตาออก ตัวหน้าต่างยังเป็น
top-level ปกติทุกอย่าง แล้วผูก `<B1-Motion>` บนแถบหัวที่วาดเองเพื่อลากหน้าต่าง

**สองเวอร์ชันในตัวเดียว (all-ages / R18)** — หน้า "สิ่งที่จะติดตั้ง" มีตัวเลือกเดียว
ที่เลือกได้จริงคือ "ฉาก R18 — adult.xp3":

| ติ๊กไว้ | ผล |
|---|---|
| ✔ (ค่าเริ่มต้นเมื่อเจอ `adult.xp3`) | แปะไทยใส่ `adult.xp3` ด้วย → ฉาก R18 เป็นไทย |
| ✘ | **ปิด** `adult.xp3` + `adult2.xp3` โดยเปลี่ยนชื่อเป็น `.off` → เกมกลับเป็น all-ages |

ทำไมต้อง "ปิด" ไม่ใช่แค่ "ไม่แปะ": `adult.xp3` ทับบทพูดใน `patch.xp3` อยู่
ถ้าปล่อยไว้เฉยๆ แล้วแปะแค่ `patch.xp3` เกมจะขึ้นภาษาจีนทั้งเกม — เป็นบั๊กเดิมเป๊ะๆ
และใช้การ **เปลี่ยนชื่อ ไม่ลบ** เพราะเป็นไฟล์ 2.3 GB ที่ผู้เล่นโหลดมา กด "ถอดแพตช์" แล้วต้องได้คืน

ผลพลอยได้: เครื่องที่ `adult.xp3` เป็น R18 build คนละตัว (แปะ diff ไม่ได้)
ยังลงเวอร์ชัน all-ages ได้ตามปกติ — ตัวติดตั้งจะพาไปหน้ารายการโดยล็อกตัวเลือกไว้
แทนที่จะบอกว่า "ลงไม่ได้" แล้วจบ

**ไม่ยัด `.xdelta` เข้าไปใน `.exe`** — ซิปมี `install.bat` ที่ใช้ไฟล์ชุดเดียวกันอยู่แล้ว
ยัดเข้าไปอีกชุดคือซิปโตขึ้น 26 MB แลกกับคำว่า "ไฟล์เดียว" ซึ่งไม่คุ้ม

**เพิ่มสองหน้าจากดีไซน์ต้นทาง** — mockup มี 4 ขั้น (locate / components / installing / done)
ของจริงเพิ่ม:
* ขั้น "ตรวจไฟล์" ใช้หน้าเดียวกับ installing (แถบเดียวกัน ต่างแค่ข้อความ) เพราะแฮช 2 GB
  กินเวลา 15-30 วิ ปล่อยจอนิ่งเฉยๆ ไม่ได้
* หน้า error — ล้มเหลวต้องบอกว่าล้มที่ไหน ไม่ใช่เงียบ

**บทพูดกับฟอนต์ติ๊กไว้และแก้ไม่ได้** — ดีไซน์ให้ทุกแถวเป็น checkbox เลือกได้
แต่สองตัวนี้เลือกไม่ได้จริง: ไม่มีบทพูดก็ไม่มีอะไรแปล ไม่มีฟอนต์ก็อ่านไม่ออก
เหลือตัวเลือกจริงตัวเดียวคือ R18 ตามตารางด้านบน

**ความคืบหน้าเป็นของจริง** — `xdelta3` ไม่มี progress ให้อ่าน จึงวัดจากขนาดไฟล์ปลายทาง
ที่โตขึ้นระหว่างทาง ไม่ใช่แถบวิ่งหลอกตา

## กับดักที่เจอมาแล้ว (อย่าเผลอทำซ้ำ)

* **ห้ามตั้ง `self._w` ใน subclass ของ widget** — tkinter เก็บ path ของ widget ไว้ในชื่อนั้น
  ทับแล้วทุกคำสั่ง Tcl จะยิงไปที่ command ผิด (`invalid command name "420"`)
* **`winfo_ismapped()` เป็น 0 เสมอตอน root ถูก withdraw** — เทสต้องใช้ `winfo_manager()`
  ไม่งั้นได้ PASS ปลอมทั้งสองทาง
* **Tk แตะได้จาก thread เดียว** — งานหนักส่งผลกลับผ่าน `queue.Queue` ที่ `after()` มาคอยดึง
* **`--windowed` ไม่มี console** ถ้าคราชตอน start ผู้เล่นเห็นแค่ "ไม่มีอะไรเกิดขึ้น"
  `app.py` จึงเขียน `installer-error.log` + เด้ง MessageBox บอกให้ไปใช้ `install.bat` แทน
* **ต้องเรียก `SetProcessDpiAwareness` ก่อนสร้าง `Tk()`** ไม่งั้นจอ 125/150% จะเบลอ
* **`after()` เปล่าๆ ได้แค่ ~46 fps** (ตัวจับเวลาของ Windows หยาบ 15.6 ms)
  `anim.py` จึงเรียก `timeBeginPeriod(1)` ตอนเริ่มมีงานและคืนให้ระบบตอนหมดงาน
  วัดได้ 46.7 → 62.0 fps
* **ยกเลิกนัด `after` ที่ค้างด้วย ไม่ใช่แค่ตั้งตัวแปรเป็น None** ไม่งั้นทวีนตัวถัดไป
  จะเห็นว่า "ว่าง" แล้วนัดเพิ่มอีกสาย กลายเป็นตัวจับเวลาหลายสายเดินขนาน
  (เทสจับได้ตอนวัดได้ 622 fps แทนที่จะเป็น 60)
* **Tk เปิด `WS_EX_LAYERED` ให้ตอนสร้าง wrapper เท่านั้น** ถ้าปิดบิตนี้ไปเอง
  `-alpha` จะเงียบไปเฉยๆ (เฟดตอนปิดไม่ทำงาน) — วัดแล้วหน้าต่างซ้อนชั้นไม่ได้
  ทำให้วาดช้าลงเลย (2.31 vs 2.30 ms/เฟรม) จึงปล่อยเปิดค้างไว้
* **`tk.Label` ไม่มีพื้นโปร่งใส** วางทับภาพพื้นหลังเมื่อไหร่คือสี่เหลี่ยมขาวทึบ
  ต้องออกแบบให้แผงภาพอยู่ในพื้นที่ที่ไม่มี widget เท่านั้น
* **PhotoImage ต้องถือ reference ไว้เอง** ถ้าปล่อยให้ตัวแปรหลุด scope
  Python จะเก็บกวาดมันทิ้ง แล้วภาพบน canvas จะหายไปเฉยๆ โดยไม่มี error
* **เปลี่ยนหน้าจอใช้ `place` ไม่ใช่ `grid`** ขยับ `pady` ของ grid ทุกเฟรม =
  Tk คำนวณผังทั้งหน้าต่างใหม่ทุกเฟรม ส่วน `place` ขยับแค่ลูกตัวเอง
* **Tk จำขนาดกรอบหน้าต่างไว้ตั้งแต่ map ครั้งแรก** — ถอด `WS_CAPTION` ทีหลังแล้ว
  `geometry("880x600")` จะได้หน้าต่าง 896x639 (กรอบเดิมกลายเป็นพื้นที่ใน)
  `_fix_size()` วัดของจริงแล้วหักออกครั้งเดียว ไม่ต้องเดาขนาดกรอบของ Windows แต่ละรุ่น
